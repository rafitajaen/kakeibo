# KB-013: AsNoTracking must be explicit on all read-only EF Core queries

**Discovered:** 2026-03-07
**Affects:** All `*Handler.cs` files under `src/Kakeibo.Api/Features/`

EF Core tracks entities loaded by default, consuming memory and CPU for change detection on every `SaveChangesAsync` call. Handlers that never modify the loaded entities must call `.AsNoTracking()` explicitly to skip change tracking.

**Rule:** Every `DbSet` query in a read-only handler (List*, Get*, Check*, Search*) must include `.AsNoTracking()` immediately after the `DbSet` access, before any `.Where()` or `.Include()` calls. Write handlers (Create*, Update*, Delete*) must NOT use `.AsNoTracking()` when they need to track changes.

| Bad | Good |
|-----|------|
| `db.Users.FirstOrDefaultAsync(...)` | `db.Users.AsNoTracking().FirstOrDefaultAsync(...)` |
| `db.Wallets.Where(...).ToListAsync()` | `db.Wallets.AsNoTracking().Where(...).ToListAsync()` |
| `db.Goals.Include(g => g.Wallet).ToListAsync()` | `db.Goals.AsNoTracking().Include(g => g.Wallet).ToListAsync()` |

**Exception:** Handlers with upsert-on-read patterns (e.g., `GetPreferencesHandler` that creates a record if none exists) should NOT add `.AsNoTracking()` if they might write after reading.
