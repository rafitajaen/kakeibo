# KB-010: Migration from Modular Monolith to Simple Monolith

**Discovered:** 2024 (early development)
**Affects:** Overall project structure, `src/`, `Kakeibo.slnx`

## Description

At approximately 5% implementation, the project was migrated from a Modular Monolith
(12 separate .NET projects) to a Simple Monolith (2 projects: Kakeibo.Api + Kakeibo.Tests).

## What Was Removed

- 12 separate project files (one per module)
- Cross-assembly contracts and interfaces
- Module client abstractions (IModuleClient pattern)
- Separate assembly references in Kakeibo.slnx

## Current Structure

- `src/Kakeibo.Api` — single assembly containing all features under `Features/{Domain}/`
- `tests/Kakeibo.Tests` — test project with `InternalsVisibleTo` access
- Domain boundaries enforced by folder conventions, not separate assemblies
- Cross-domain queries use direct DI injection (not module clients)

## Rationale

- Reduced complexity for a team of one
- Eliminated over-engineering for the current scale
- Faster development cycles
- No loss of domain separation — folder structure enforces boundaries

**Rule:** Do not re-introduce separate project files per domain. The simple monolith is the
canonical and intentional architecture for this project.
