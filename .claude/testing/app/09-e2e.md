# 09 — Tests E2E con Playwright

---

## Cuándo escribir E2E vs unit

**Escribe E2E cuando:**
- El flujo involucra navegación entre páginas (`/login` → `/` → `/wallets`)
- El comportamiento depende de autenticación o guards del router
- Quieres validar que toda la cadena (componente → store → router) funciona junta
- Es un flujo crítico de negocio (registro, onboarding, crear wallet, añadir transacción)

**Escribe unit test cuando:**
- Solo necesitas verificar la lógica de un store o componente aislado
- El comportamiento no involucra navegación
- Quieres feedback rápido durante el desarrollo

**Regla de oro:** un test E2E por flujo crítico de usuario, tests unitarios para
todo lo demás.

---

## Cómo mockear APIs con `page.route()`

En Kakeibo los E2E **no** dependen de una API real. Todas las llamadas HTTP se
interceptan con `page.route()` antes de navegar.

```typescript
import { test, expect } from "@playwright/test";

test("shows budget list for authenticated user", async ({ page }) => {
    // 1. Mockear autenticación
    await page.route("**/api/auth/me**", (route) => {
        route.fulfill({
            status: 200,
            body: JSON.stringify({
                id: "user-1",
                email: "test@example.com",
                role: "User",
                currency: "EUR",
                isVerified: true,
                name: "Test User",
            }),
        });
    });

    // 2. Mockear wallets (necesario para evitar redirección a onboarding)
    await page.route("**/api/wallets**", (route) => {
        route.fulfill({
            status: 200,
            body: JSON.stringify([
                { id: "w-1", name: "Checking", type: "Personal",
                  currency: "EUR", balance: 1000, isArchived: false,
                  createdAt: "2026-01-01T00:00:00Z" },
            ]),
        });
    });

    // 3. Mockear el endpoint específico de la página
    await page.route("**/api/budgets**", (route) => {
        route.fulfill({
            status: 200,
            body: JSON.stringify([
                { id: "budget-1", name: "Food Budget", categoryId: "cat-1",
                  categoryName: "Food & Dining", limit: 400, startDate: "2026-01-01",
                  endDate: "2026-01-31", walletId: null, walletName: null,
                  currentSpending: 120, createdAt: "2026-01-01T00:00:00Z" },
            ]),
        });
    });

    // 4. Navegar a la página (después de los mocks, no antes)
    await page.goto("/budgets");

    // 5. Verificar que el contenido esperado aparece
    await expect(page.getByText("Food Budget")).toBeVisible({ timeout: 5000 });
    await expect(page.getByText("120")).toBeVisible({ timeout: 5000 });
});
```

**Importante:** registra los mocks con `page.route()` **antes** de `page.goto()`.
Playwright intercepta las peticiones en orden de registro; las que llegan antes de
que la página cargue necesitan estar registradas primero.

## Cómo testear redirecciones de autenticación

```typescript
test("unauthenticated user is redirected to /login", async ({ page }) => {
    // La API devuelve 401 → el guard redirige a /login
    await page.route("**/api/auth/me**", (route) => {
        route.fulfill({ status: 401 });
    });

    await page.goto("/wallets");

    // Verificar la redirección
    await expect(page).toHaveURL(/\/login/, { timeout: 5000 });
});

test("authenticated user on /login is redirected to /", async ({ page }) => {
    await page.route("**/api/auth/me**", (route) => {
        route.fulfill({
            status: 200,
            body: JSON.stringify({
                id: "user-1", email: "test@example.com", role: "User",
                currency: "EUR", isVerified: true, name: "Test User",
            }),
        });
    });
    await page.route("**/api/wallets**", (route) => {
        route.fulfill({ status: 200, body: JSON.stringify([{ id: "w-1", name: "Checking",
            type: "Personal", currency: "EUR", balance: 100,
            isArchived: false, createdAt: "2026-01-01" }]) });
    });

    await page.goto("/login");

    await expect(page).toHaveURL(/\/$|\/onboarding/, { timeout: 5000 });
});
```

## Testear un flujo completo de usuario

```typescript
import { test, expect } from "@playwright/test";

const mockUser = {
    id: "journey-user",
    email: "journey@example.com",
    role: "User",
    currency: "EUR",
    isVerified: true,
    name: "Journey User",
};

const mockWallet = {
    id: "w-1", name: "My Wallet", type: "Personal",
    currency: "EUR", balance: 5000, isArchived: false, createdAt: "2026-01-01",
};

test.describe("Full User Journey", () => {
    test("authenticated user can navigate dashboard → settings → dashboard", async ({ page }) => {
        // Mock todos los endpoints que se llaman durante la navegación
        await page.route("**/api/auth/me**", (route) =>
            route.fulfill({ status: 200, body: JSON.stringify(mockUser) })
        );
        await page.route("**/api/wallets**", (route) =>
            route.fulfill({ status: 200, body: JSON.stringify([mockWallet]) })
        );
        await page.route("**/api/users/me/sessions**", (route) =>
            route.fulfill({ status: 200, body: JSON.stringify([]) })
        );

        // Ir a dashboard
        await page.goto("/");
        await expect(page).toHaveURL(/\/$|\/#/, { timeout: 5000 });

        // Navegar a settings
        await page.goto("/settings");
        await expect(page.getByText(/profile/i)).toBeVisible({ timeout: 5000 });

        // Volver a dashboard
        await page.goto("/");
        await expect(page).toHaveURL(/\/$|\/#/, { timeout: 5000 });
    });

    test("new user without wallets is redirected to /onboarding", async ({ page }) => {
        await page.route("**/api/auth/me**", (route) =>
            route.fulfill({ status: 200, body: JSON.stringify(mockUser) })
        );
        await page.route("**/api/wallets**", (route) =>
            route.fulfill({ status: 200, body: JSON.stringify([]) }) // sin wallets
        );

        await page.goto("/");

        await expect(page).toHaveURL(/\/onboarding/, { timeout: 5000 });
        await expect(page.getByText(/welcome/i)).toBeVisible({ timeout: 5000 });
    });
});
```

## Inventario de specs E2E actuales

| Spec | Flujos cubiertos |
|------|----------------|
| `e2e/auth.spec.ts` | Redirección no autenticado, login form visible, guest route redirect |
| `e2e/home.spec.ts` | Dashboard carga y muestra secciones principales |
| `e2e/full-journey.spec.ts` | Dashboard→Settings→Dashboard, onboarding sin wallets, acceso protegido múltiple |
| `e2e/onboarding.spec.ts` | Flujo de onboarding, creación de primera wallet |
| `e2e/wallets.spec.ts` | Redirección sin auth, listado de wallets (comentado: requiere API) |
| `e2e/transactions.spec.ts` | Redirección sin auth, flujo de transacción (comentado: requiere API) |
| `e2e/budgets.spec.ts` | Redirección sin auth, gestión de budgets (comentado: requiere API) |
| `e2e/goals.spec.ts` | Redirección sin auth, gestión de goals (comentado: requiere API) |
| `e2e/recurring.spec.ts` | Redirección sin auth, patrones recurrentes (comentado: requiere API) |
| `e2e/settings.spec.ts` | Redirección sin auth, tabs de settings, cambio de nombre de perfil |

**Nota sobre tests comentados:** Los flujos que requieren una API viva están comentados
con instrucciones para ejecutarlos manualmente. Se activan al levantar la API local.

## Cómo añadir un nuevo spec E2E

1. Crear `e2e/{dominio}.spec.ts`
2. Añadir siempre el test de redirección sin auth como primer test
3. Mockear `**/api/auth/me**` y `**/api/wallets**` en todos los tests que requieren auth
4. Usar `{ timeout: 5000 }` en todas las assertions `toBeVisible` y `toHaveURL`
5. Comentar los flujos que requieren API viva con instrucciones de ejecución manual

```typescript
import { test, expect } from "@playwright/test";

test.describe("MyFeature", () => {
    // Test 1 siempre: guard de autenticación
    test("unauthenticated user is redirected to login", async ({ page }) => {
        await page.route("**/api/auth/me**", (route) => {
            route.fulfill({ status: 401 });
        });
        await page.goto("/my-feature");
        await expect(page).toHaveURL(/\/login/);
    });

    // Tests siguientes: flujos con auth mockeada
    test("shows empty state for new user", async ({ page }) => {
        await page.route("**/api/auth/me**", (route) =>
            route.fulfill({ status: 200, body: JSON.stringify({ /* usuario */ }) })
        );
        await page.route("**/api/wallets**", (route) =>
            route.fulfill({ status: 200, body: JSON.stringify([{ /* wallet */ }]) })
        );
        await page.route("**/api/my-feature**", (route) =>
            route.fulfill({ status: 200, body: JSON.stringify([]) })
        );

        await page.goto("/my-feature");
        await expect(page.getByText(/no items/i)).toBeVisible({ timeout: 5000 });
    });

    // Tests de flujo completo (comentados, requieren API viva)
    // Descomenta y ejecuta con: bun run app:test:e2e --grep "full flow"
    //
    // test("full flow: create → list → delete", async ({ page }) => {
    //   ...
    // });
});
```

## Comandos de depuración

```bash
# Ver el navegador mientras corre el test
bun run app:test:e2e --headed

# Modo UI interactivo: selecciona y depura tests uno a uno
bun run app:test:e2e --ui

# Pausar en cada paso (abre DevTools del navegador)
bun run app:test:e2e --debug

# Ejecutar un solo spec
bun run app:test:e2e e2e/auth.spec.ts

# Ejecutar tests que coinciden con un patrón de nombre
bun run app:test:e2e --grep "unauthenticated"

# Ver el reporte HTML del último run
bunx playwright show-report
```

## Buenas prácticas en E2E

**Registra los mocks antes de navegar.** `page.route()` debe llamarse antes de `page.goto()`.

**Usa `{ timeout: 5000 }` en assertions async.** El router y los stores son asíncronos;
sin timeout, los tests fallan intermitentemente.

**Mocka exactamente lo que la página necesita.** Si la página llama a 3 endpoints,
mockea los 3. Un endpoint sin mock hará que la llamada salga a internet (o falle).

**No uses `page.waitForTimeout()`.** Es frágil. Usa `expect(...).toBeVisible()` con
timeout, que espera activamente hasta que el elemento aparece.

**Mantén los datos de mock simples.** El mínimo necesario para que el test funcione.
Datos excesivamente detallados hacen los tests difíciles de mantener.
